Server responses
  • 201Created. Open the room or the game link.
  • 400Name too short or too long: state 4 or 5.
  • 409 name_takenState 6.
  • 409 already_signed_inThis browser has a session (another tab). Read /api/me and go on. No error shows.
  • GET /api/auth/methodsDecides which of states 1 to 10 show. A failure gives state 14. The name form shows only when guest is true.
  • Google callback, oauth_failedState 11. The browser comes back to the sign-in screen.
  • Google callback, new userState 12. A known Google user goes straight in, and the page reloads signed in.
  • POST /api/auth/google/name 409 name_takenState 13.
  • GET /api/auth/google/start 409 already_signed_inNo error shows. A signed-in user does not see this screen.
  • 5xx or no networkState 8. The field keeps the name.

Keyboard and screen reader

  • LabelA visible label, tied with for and id. The placeholder is only an example.
  • Hint and errorsaria-describedby points to the hint or the error. Invalid state sets aria-invalid="true".
  • Error announcementThe error has role="alert", so it is read when it appears. Focus stays in the field.
  • CounterThe 0/16 counter is aria-hidden. The 16 limit is in the hint, so typing does not make noise.
  • Enter submitsThe field is in a form. Enter in the field presses Continue. Checks run on submit, and again while typing after the first error.
  • Focus ring2px #e9f0ea outline, 2px offset, on the field and the button (:focus-visible). On load, focus goes to the field.
  • Targets and busy stateField and button are at least 44px high. While busy, the button uses aria-disabled and aria-busy, and the field is read-only. Focus is not lost.
  • ContrastInk and ink soft on ground pass 4.5:1. Accent ink on accent is 5.2:1. An error uses an icon and text, not only colour.
