# Glossary

This file gives the meaning of the project terms and tells where the code and the docs use them. Use these words in code, docs, commits and task lists.

- Each table row has a term, its meaning, and the main files that use it.
- **(planned, M2)** or **(planned, M3)** marks a term that is only in the plan. The code does not have it yet.
- The game rules (square, rent, jail, auction, trade, debt, bankruptcy, Start salary) are in [plan/game-rules-reference.md](plan/game-rules-reference.md). This file does not repeat them.

## Confusing terms

Some words have more than one meaning. Use the word in the "Use this" column. Do not use the words in the last column.

| Word              | Meanings                                                                                                   | Use this                                                                                                                                                                              | Do not use                                                                                                         |
| ----------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| token             | 1. A game piece on the board. 2. The random secret in the session cookie. 3. A `--hf-*` CSS variable       | **token** (or **player token**) for the game piece. **Session token** for the secret. **Design token** for the CSS variable                                                           | "token" alone for a session token or a design token. "Pawn" (only the CSS names `--hf-pawn-*` keep it)             |
| avatar, figure    | The look of a token                                                                                        | **Avatar**: the 2D outline icon of a token. **Figure**: the 3D model of a token                                                                                                       | "avatar" for the 3D model                                                                                          |
| owner, host       | 1. The user who created the game. 2. The player who owns a property                                        | **Host** for the user who created the game. The code names stay `ownerId`, `isOwner` and `not_game_owner`. **Property owner** for `Ownership.ownerId` and the engine code `not_owner` | "Session owner" (old name in [plan/game-screen-2-gameplay.md](plan/game-screen-2-gameplay.md) §3.1), "owner" alone |
| game, room, lobby | The game entity, the waiting screen, the list page                                                         | **Game**: the entity (`Game`, the `games` table). **Game room**: the screen at `/games/:id` while the game is `waiting`. **Lobby**: the page with the public game list (M2)           | "Room" for the entity, "lobby" for the game room                                                                   |
| seat, player      | A person at the table                                                                                      | **Seat**: the API and database entity (`Seat`, the `seats` table). **Player**: the engine entity (`Player`). A seat and its player have the same id                                   | "Seat order" for turn order. `createGame` shuffles the turn order                                                  |
| device            | The browser that a person uses                                                                             | **Device**: one signed-in user in one browser or browser profile. In the data it is the `controllerUserId` of a seat. It is not a table                                               | "Client", "session" for this meaning                                                                               |
| guest             | 1. A player who is not the host of a room. 2. A guest user, made by guest sign-in for test and development | **Guest** (room): a player who is not the host. **Guest user**: a user from guest sign-in. Say which one in text where it is not clear                                                | "Guest" alone for a Google user                                                                                    |
| version           | A counter                                                                                                  | **Version**: the engine state version. It increases by one for each accepted action. `games.version`, the stream envelope `version` and the SSE `id` use the same number              | "Revision", "sequence"                                                                                             |
| snapshot          | A full copy of the state                                                                                   | Always add a qualifier: **snapshot message** (stream type `snapshot`), **game snapshot** (a `game_snapshots` row), **store snapshot** (`useGameSnapshot`)                             | "Snapshot" alone                                                                                                   |
| leave             | Two different actions                                                                                      | **Leave the room**: `POST /api/games/:id/leave` while the game is `waiting`. **Leave game**: the game screen flow that sends `Resign`                                                 | "Leave" for resign in the API                                                                                      |
| Start, Go         | Square 0                                                                                                   | **Start** in the UI and the docs. The code keeps `GO_SQUARE`, `GO_SALARY`, `PassedGo` and `kind: "go"`                                                                                | "Go" in UI text                                                                                                    |
| out of the game   | A player who cannot play now                                                                               | **Eliminated**: `Player.active` is `false`. **Bankrupt** and **resigned** are the two causes                                                                                          | "Spectator", "inactive" in UI text                                                                                 |

| Redacted state                        | The `GameState` without `rng` and `decks`. Only this state leaves the server                                                    | [redact.ts](apps/api/src/game/redact.ts), [state.ts](packages/shared/src/state.ts)              |

| GameService                           | Loads the state, checks the seat, calls `applyAction`, stores the events and publishes them                                     | [game/service.ts](apps/api/src/game/service.ts)                                                 |

| Round                                 | Not an engine value. Round = 1 + floor(`TurnEnded` events / seats at start)                                                     | [result.ts](packages/shared/src/result.ts)                                                      |

## Known inconsistencies

These items are recorded here. They are not fixed yet.

- **Type names used twice.**
  - `GameStatus`: the game status in [games.ts](packages/shared/src/games.ts), and the load status in the web [store.ts](apps/web/src/game/store.ts).
  - `CreateGameInput`: the engine input in [game.ts](packages/game-engine/src/game.ts), and the API body in [games.ts](packages/shared/src/games.ts).
  - `mayAct`: in the engine and in the web selectors, with different signatures.
  - `Turn` (web view model, [useTurn.ts](apps/web/src/screens/game/turn/useTurn.ts)) and `TurnState` (engine).
  - `MAX_SEATS` (shared) and `MAX_PLAYERS` (engine) have the same value.
- **Helpers written more than once.**
  - `formatMoney` in [format.ts](apps/web/src/screens/game/turn/format.ts), [PlayerRow.tsx](apps/web/src/screens/game/rail/PlayerRow.tsx) and [describe.ts](apps/web/src/screens/game/log/describe.ts), and `money` in [handModel.ts](apps/web/src/screens/game/hand/handModel.ts).
  - `consequenceText` in [debtModel.ts](apps/web/src/screens/game/flows/debt/debtModel.ts) and [consequence.ts](apps/web/src/screens/game/flows/leave/consequence.ts).
  - `playerName` in [describe.ts](apps/web/src/screens/game/log/describe.ts) and [debtModel.ts](apps/web/src/screens/game/flows/debt/debtModel.ts).
  - `DECK_LABELS` in [cardText.ts](apps/web/src/screens/game/flows/card/cardText.ts) and [tradeModel.ts](apps/web/src/screens/game/flows/trade/tradeModel.ts).
- **Deck name.** The rules say "Chest". [cardText.ts](apps/web/src/screens/game/flows/card/cardText.ts) says "Community Chest".
- **Terrier name.** The code key is `dog`. The spec says "Scottish terrier" and "Terrier".
- **Spelling.** The docs and the UI use British spelling ("colour", "centre"). Code names use `color` (`GROUP_COLORS`) and `cssColor`.
- **Instructions file name.** The file is `CLAUDE.MD`. The docs write `CLAUDE.md`.
- **Phase names.** The phase names in [game-screen-2-gameplay.md](plan/game-screen-2-gameplay.md) ("Start of turn", "In debt", "Turn resolved") do not map one to one to the engine `awaiting_*` phases.
